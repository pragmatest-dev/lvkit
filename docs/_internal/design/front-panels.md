## Requirements
1. A VI's front panel is drawn faithfully: tab controls show their selected page with the tabs; splitter panes sit side by side or stacked, each clipped; scrolled panels are placed by their scroll offset; free labels and decorations are drawn; objects stack in LabVIEW's order.
2. **Viewer and visual diff (maintainer, 2026-11-07):** each has a tab to switch between **Block Diagram** and **Front Panel**. A VI opens on Block Diagram. A `.ctl` shows only its Front Panel (no tab). Both VS Code viewers (desktop and web) show lvkit's own HTML (`editors/vscode/extension.js:441` runs `lvkit render --format html`; the web extension calls `cached_render`, `web/extension.js:647`), and the diff viewer is `render/diff_viewer.py:42` over `templates/diff_viewer.html`, so the tab is built once, in lvkit's HTML, and every frontend gets it.
3. Every view keeps its current output for the block diagram; nothing about the diagram changes.

## Step 1. Parser: the panel's structure (one PR)
New module `parser/fp_structure.py` (`parser/vi.py` is the large file); types in `parser/models.py` next to `ParsedFrontPanel`.
- `ParsedFrontPanel.layout`: a tree of `ParsedFPPane` (bounds, scroll origin, objects) and `ParsedFPSplitter` (bounds, ratio, side-by-side, first, second), read from `root/paneHierarchy` (`pane` or `splitter`, recursive through `topOrLeft`/`botOrRight`).
- A pane's objects, in list order (first = topmost): controls (the existing `_parse_ddo` path), `ParsedFPLabel` (text, bounds, colours, hidden, font runs), `ParsedFPDecoration` (bounds, `ImageResID` shape, colours), `ParsedFPGrouper` (its own objects, grouper-local).
- A tab control gains `tab_pages` (name from `tabControlPageInfoArray/PageInfoItem/caption`, hex text; tab-local bounds; its own objects) and `tab_selected` (the page whose name equals the tab's shown label text; `DefaultData` / `tabControlPageSelValue` agree wherever present).
- `ParsedFrontPanel.controls` stays the flat list in today's order, so `dco_order`, the graph's off-pane terminals and every current view are unchanged. A control's own `bounds` stay as stored; placement is computed by the renderer from the tree.
- Tests: one tiny handmade `_FPHb.xml` per construct (plain pane with a scroll origin, splitter side by side and stacked, nested splitter, tab with two pages and a selected page, grouper, free label, decoration), asserting the parsed tree exactly; corpus checks on Main.vi (lv-flex), Create Measurement Client.vi, Line Configuration Dialog.vi, JKI Graphical Test Runner Main UI.

## Step 2. Render a VI's panel (one PR)
- `render/front_panel/geometry.py` `build_boxes` walks the tree: window position = splitter pane offsets + pane scroll origin + stored bounds, clipped to the pane; a tab control draws its tabs and only its selected page's objects; grouper children offset by the grouper; each object list drawn last-to-first.
- Free labels and decorations get glyphs. Decoration shapes come from a table keyed by `ImageResID`, extended from corpus evidence as the block-diagram one was (`render/glyphs/decorations/factory.py`); an unknown id draws its bounds as a plain box.
- Class-object controls (`udClassDDO`, 1,003 corpus files) use the block-diagram class glyph (`render/glyphs/nodes/class_glyph.py`) instead of the dashed placeholder.
- `lvkit render X.vi` keeps writing the block diagram; `--view front-panel` writes the panel (SVG or HTML). A `.ctl` renders its panel as today. MCP `render` takes the same `view`.
- Checked against screenshots of real corpus panels, as the `.ctl` renderer was.

## Step 3. The Block Diagram / Front Panel tab (one PR)
- **A "hidden" toggle on the views (maintainer, 2026-11-07: "Need a hidden toggle on views").** Hidden objects (a control, cluster field, free label or part whose hidden bit is set) are drawn into the SVG in their own group with a class (`lv-hidden`), invisible by default; the viewer page, the combined SVG and the diff viewer get a toggle that shows them faded (as LabVIEW's editor shows hidden objects when asked). A static SVG with no script shows the panel as it looks when run (hidden objects invisible). **The toggle also sets what "fit" frames (maintainer, 2026-11-07: "If hidden fit will show only visible/window view. If not hidden fit shows bounding box of all controls")**: hidden (the default) fits the view to the saved window; shown fits it to the bounding box of every object, hidden ones and those outside the window included. The SVG carries both rects (the window frame and the whole extent) so the viewer's fit can use either; the static SVG's viewBox is the window. Today Step 2 skips hidden objects (`render/front_panel/geometry.py` `_place_objects`, `build_boxes`); this changes it to "place them, mark them".
- **`--view combined`** (maintainer, 2026-11-07: "Maybe a 'combined' for a single svg with tab swap?"): one file holding both pictures with a Block Diagram / Front Panel switch, the block diagram shown first. As HTML it is the tabbed viewer page. As SVG it is one self-contained interactive SVG with two tabs that swap the pictures (maintainer: "Since we can have an interactive svg"; "And the viewer will be better"): the swap is one more inline script added the way the diagram SVG already adds its frame and hover scripts (`render/__init__.py:546-560`, root id + `__ROOT_ID__`), and without script (an `<img>`, a doc page) the block diagram shows, as the diagram SVG already degrades (`:380-385`). The viewer page is built on the combined SVG, so the viewer, the SVG and the diff viewer share one swap.
- `render --format html` of a VI embeds both pictures and a two-tab switch, Block Diagram first and selected; a `.ctl` page has only the panel and no tab. The theme control, properties and connector-pane panels stay as they are on the Block Diagram tab.
- The diff viewer gets the same tab. Front Panel shows the two panels side by side, each control marked added / removed / changed, correlated by its front-panel uid as the VI diff already does (`graph/diff.py:1842`, `:1931`). `lvkit diff` text and JSON gain the panel changes the picture shows (position, size, colour, default value, tab page), and `diff` accepts `.ctl` files (#130).
- VS Code: no extension change beyond the version bump, since the HTML carries the tab.

## Decode results (`.tmp/fp_origin_findings.md`, second research pass)
- **Scroll offset.** The saved window shows stored positions shifted by the pane's `origin` (x first): with that rule the window lies inside the panel's scroll extent (`docBounds`) in 98.3% of 1,819 panels; any other sign or order gives 34–52%. A panel is often larger than its window: 83.3% of panels have every control inside the window, 4.1% have only hidden controls outside it, 8.8% have controls outside the window but inside the scroll extent, 3.3% outside both (mostly typedef instances bigger than the window with a stale extent), 0.5% have no extent. The window's size is the pane's `bounds` size; `pBounds` (today's `panel_bounds`) is `(0,0,0,0)` in 7% of files. Four window-sized backdrops fit only with `origin.y + pane top`; that is not general (386 files with a negative top fit `origin` alone in 88%), so `origin` alone is the rule.
- **Containers in LabVIEW 8.5.** Page controls and grouper children are stored panel-absolute in the two LabVIEW 8.5 VIs (one tab control, six groupers) and container-local in 9.0 and later (7 tab controls, 233 groupers); no flag tells them apart, so the rule is the VI's saved version. Only two 8.5 VIs have containers, so this is thin evidence; no 8.0/8.2 sample has one.
- **Selected tab** is confirmed by a second field: the tab array's label part sits at the selected tab's position (left 0 for the 154 first-tab controls, 114 / 104 for the two third-tab ones, matching tab widths from `textWidth`). `frontRow` is the tab row's rectangle.
- **Decorations.** NI's public docs name no shapes by id (https://docs-be.ni.com/api/bundle/labview/page/using-decorations-on-the-front-panel.html). From corpus shape: `-412` the panel backdrop, `-117`/`-115` arrow heads, `-504`/`-503` thin lines, positive ids embedded pictures; the rest unknown and drawn as their box.
- **Fonts.** A font table entry's `Prop2` is the size (a label is size + 2 px high in 69% of labels).

## Decisions for the maintainer
1. **DECIDED (maintainer, 2026-11-07): a switch, with a "both" choice.** `lvkit render X.vi --view block-diagram|front-panel|both` (`block-diagram` is the default for a VI; a `.ctl` has only its panel). **`both` is two files (maintainer, 2026-11-07: "Both is two files")**: the block diagram and the front panel, each its own SVG or HTML file; the tabbed viewer page is what the HTML viewer shows (decision 2). MCP `render` takes the same `view`.
2. **DECIDED (maintainer, 2026-11-07): "The viewer should do both".** The viewer page (VS Code desktop and web, and the diff viewer) carries both pictures, with the Block Diagram / Front Panel tab.
3. **DECIDED (maintainer, 2026-11-07): Step 1 → 2 → 3 as three PRs.**
4. **DECIDED (maintainer, 2026-11-07): the whole panel, with the saved window's edge drawn as a thin frame** (8.8% of panels have controls outside their window; a diff or a doc page shows them).
